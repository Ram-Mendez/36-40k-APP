# 48 · Una compra completa sigue como parcial

[ProcurementRepository.updateReceiptStatus(long id)](../../../../src/main/java/com/acme/operations/procurement/ProcurementRepository.java) decide el estado al recibir una compra. Si alguna de sus líneas sigue pendiente, asigna `PARTIALLY_RECEIVED`. Si todas están recibidas, asigna `RECEIVED`.

El siguiente fragmento Java de práctica contiene un fallo.

```java
jdbc.update("""
    UPDATE purchase_order
    SET status = CASE WHEN EXISTS (
        SELECT 1 FROM purchase_order_line
        WHERE received_quantity < quantity
    ) THEN 'PARTIALLY_RECEIVED' ELSE 'RECEIVED' END
    WHERE id=?
    """, id);
```

[48.sql](48.sql) muestra el estado calculado para las compras `202` y `204`. Ambas salen como `PARTIALLY_RECEIVED`.

| id | calculated_status |
| ---: | --- |
| 202 | PARTIALLY_RECEIVED |
| 204 | RECEIVED |

**Pista.** La compra `202` tiene líneas pendientes. En la `204` se pidieron 4 unidades y se recibieron las 4. ¿Qué líneas consulta `EXISTS` para cada compra?
