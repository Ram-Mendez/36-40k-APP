# 04 · An order appears again on the next page

**Task.** The screen shows two orders per page. Newest orders come first. For orders created on the same date, the lower ID comes first.

1. **Predict.** There are five orders. Write down how many rows pages `0`, `1`, `2`, and `3` should contain. 3
2. **Reproduce.** In [04.sql](04.sql), change `VALUES (1, 2)` to `VALUES (0, 2)` and run it. Note both IDs. Restore `(1, 2)` and run it again. Which ID appears twice?
3. **Inspect the full list.** Run the query below. Mark where the second page should start. Count how many rows you need to skip.

   ```sql
   SELECT p.id, p.creado
   FROM sql_lab10.pedidos AS p
   ORDER BY p.creado DESC, p.id ASC;
   ```

4. **Write your change.** Change how your copy calculates `OFFSET`. With two rows per page, the first three pages skip 0, 2, and 4 rows. Try a page size of 3 and predict how many rows page 1 should skip.
5. **Check.** With size 2, expect `[102, 103]`, `[104, 105]`, `[101]`, and an empty page. With size 3, page 1 contains `[105, 101]`.

<details><summary>If you get stuck</summary>

Hint 1. `LIMIT` sets how many rows to return. `OFFSET` sets how many rows to skip from the start.

Hint 2. Both values needed to calculate the offset are in `parametros`. Sorting by date and ID gives a consistent order even when dates tie.

</details>
