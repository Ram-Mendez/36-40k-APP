# 06 · The report is empty when the start date is missing

Sales wants completed orders from before November 2. Leaving **from** blank allows any date before the cutoff. The **to** date is excluded.

1. **Identify the starting rows.** Run `SELECT id, creado FROM sql_lab10.pedidos WHERE estado = 'COMPLETED' ORDER BY id;`. Order 101 is from November 1. Orders 102 and 104 are from November 2. Write down which should pass the filter.
2. **Reproduce.** Copy [06.sql](06.sql) into the `lab_20261117` console. Select from `WITH` through the semicolon and press **Ctrl+Enter**. You get zero rows. The `VALUES` line contains the two inputs, in the order `desde` (from), `hasta` (to).
3. **Isolate one comparison.** Run `SELECT DATE '2026-11-01' >= CAST(NULL AS date) AS pasa_desde;`. Look at the cell containing `NULL`. A `WHERE` clause keeps a row only when its condition is `true`.
4. **Write your change.** Say out loud when the November 1 row should pass. It passes if the start date is blank or the order date is on or after the start date. Put those two checks in one condition in parentheses. For a syntax hint, look at how the `hasta` line handles a missing date.
5. **Check each combination.** Change only the two inputs in `VALUES`. Use `CAST(NULL AS date)` for a blank and, for example, `DATE '2026-11-02'` for a date.

| From (included) | To (excluded) | Expected IDs |
| --- | --- | --- |
| blank | November 2, 2026 | 101 |
| November 2, 2026 | blank | 102, 104 |
| November 1, 2026 | November 2, 2026 | 101 |
| blank | blank | 101, 102, 104 |
