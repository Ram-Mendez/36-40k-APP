# BOP-113 — Pedidos pendientes por transporte lento

**Categoría:** integración y fallo operativo. **Prioridad:** alta durante el incidente.

**Contexto:** al completar pedidos aparecen 503 y el área comercial pregunta si debe crear de nuevo los pedidos. La incidencia se simula configurando el carrier lento; el backend base debe conservar reservas.

**Comportamiento esperado:** diagnosticar usando requestId, duración, health y SQL; comprobar que no hubo consumo; restaurar dependencia y reintentar el mismo pedido.

**Criterios de aceptación:** evidencia de timeout acotado, estado CONFIRMED, físicas intactas, reservas mantenidas y ausencia de movimiento SHIP; recuperación deja una única expedición. Elaborar nota operativa de causa observada y acciones, sin aumentar timeouts de forma indiscriminada.

**Reproducción mínima:** usar modos de fallo documentados en el carrier de `infra/carrier` o ejecutar `ShippingClientTest#slowCarrierIsBoundedByReadTimeout` y `BusinessIntegrationTest#carrierFailurePreservesConfirmedOrderAndReservationForRetry`. Para el ejercicio manual seguir `CONTROLLED-DEBUGGING.md`.
