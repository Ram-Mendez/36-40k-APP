# BOP-114 — Contratar expedición con proveedor real

**Categoría:** integración HTTP. **Prioridad:** futura, requiere contrato proveedor.

**Contexto:** actualmente se consulta una cotización sin efecto remoto. PO desea que completar contrate un envío y obtenga seguimiento. El contrato del proveedor aún no existe en este repositorio.

**Comportamiento esperado:** definir primero un contrato simulado de POST con clave idempotente y consulta de resultado; una respuesta perdida no debe contratar dos envíos ni consumir stock dos veces.

**Criterios de aceptación:** documentar estados intermedios y recuperación de respuestas ambiguas; timeouts; idempotencia proveedor/cliente; pruebas de fallo antes/después del efecto remoto y reconciliación; no mantener bloqueos PostgreSQL durante HTTP; auditoría sin secretos. Aprobar el diseño de estados antes de implementar la ampliación.

**Evaluación:** simular que el proveedor acepta el envío y corta la respuesta. El sistema debe poder averiguar qué ocurrió. No afirmar atomicidad entre HTTP y PostgreSQL porque ambas llamadas estén dentro de un método @Transactional.
